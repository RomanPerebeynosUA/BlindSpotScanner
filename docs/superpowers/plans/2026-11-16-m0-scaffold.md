# M0 Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An empty, buildable, tested BlindSpotScanner skeleton: `docker compose up` serves an empty Angular shell and the API's `/health` returns 200.

**Architecture:** One .NET 10 solution with the Clean Architecture projects (Domain ← Application ← Infrastructure ← Api/Worker) and three test projects. An Angular 22 workspace in `src/web`. Docker Compose runs four containers (db, api, worker, web); nginx serves the Angular build and proxies `/api` and `/hubs` to the api. A GitHub Actions workflow builds, lints and tests both sides.

**Tech Stack:** .NET SDK 10.0.102, ASP.NET Core 10, xUnit, FluentAssertions 7.x, Microsoft.AspNetCore.Mvc.Testing · Angular CLI 22.2.7, Vitest (Angular default), angular-eslint · postgres:16, nginx · GitHub Actions.

**Spec:** `BlindSpotScanner-Blueprint/docs/11-implementation-plan.md` (M0), plus `03-backend-dotnet.md` (layout), `10-security-config-ops.md` (deployment), `docs/DECISIONS.md`, and the root `CLAUDE.md`.

## Global Constraints

- Root `CLAUDE.md` wins over the blueprint (D2). Use names `BlindSpotScanner.*` (D5). Use .NET 10 + Angular 22 (D1).
- All C# projects: `Nullable` enabled and `TreatWarningsAsErrors` true.
- References: Domain → none. Application → Domain. Infrastructure → Application. Api and Worker → Infrastructure (and therefore Application). Tests reference only what they test.
- No speculative complexity. Do not add Serilog, OpenTelemetry, EF Core, Angular Material, SignalR, OpenAPI or auth in M0. Each arrives with the milestone that uses it.
- Angular uses the 2025 file naming style (`app.ts`, `app.html`, `app.spec.ts`), per D7 (this plan adds it).
- Assertions use FluentAssertions **7.x**, pinned to an exact version, per D8 (this plan adds it).
- No secrets in the repo: commit `.env.example` and keep `.env` gitignored (it already is).
- Tests are named `Method_Scenario_ExpectedResult`, use `// Arrange`, `// Act`, `// Assert` comments, and test one behavior each.
- Use Serena tools to read and edit code. Before using an API whose shape matters (WebApplicationFactory in .NET 10, `ng add angular-eslint`, GitHub Action major versions), look it up with context7.
- Conventional Commits, on branch `feature/m0-scaffold`. Never push without asking.

## Review Focus

1. **`.env` missing** on `docker compose up`. Compose should stop with a message that names the missing variable, not start postgres with an empty password. Task 4 uses `${VAR:?message}` and checks it.
2. **Deep-link refresh** (`/repos/123` loaded directly from nginx). nginx should return `index.html` (200), not 404. Task 4 checks it.
3. **An unknown `/api/...` path through nginx** should return the api's 404, not `index.html`. Task 4 checks it.
4. **SignalR through nginx** needs the WebSocket `Upgrade`/`Connection` headers on `/hubs`. There's no hub to test until M6, so Task 4 configures the headers and M6 must test them.
5. **Template code vs `TreatWarningsAsErrors`.** Template leftovers (`Class1.cs`, `UnitTest1.cs`, the sample `Worker.cs`) must be removed, and the build must pass with zero warnings. Task 1 checks it.
