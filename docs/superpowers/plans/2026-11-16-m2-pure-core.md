# M2 Pure Core (Assembler, Validator, Comparer) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Docs 06, 07 and 08 as pure C# in Application:
- `RunComparer` computes the delta.
- `ReportAssembler` computes everything code owns: the summary, controller rollups, risk ranks and the delta.
- `ReportValidator` re-derives everything and checks the doc 07 checklist.

The examples are the golden files.

**Architecture:**
- All three live in `src/BlindSpotScanner.Application/Reports/`. They are pure, with no I/O and no clock. The assembler and comparer are static classes.
- The validator has one port, `IReportSchemaValidator`, for checklist item 1. Infrastructure's existing `ReportSchemaValidator` implements it.
- The validator re-derives the report by calling the assembler on the report's own detail, then diffs the canonical JSON field by field. Every tampered number yields a named violation.

**Tech Stack:** .NET 10, the Domain report records and `ReportJsonSerializer` (M1), xUnit 2.9.3 and FluentAssertions 7.2.2.

**Spec:** `BlindSpotScanner-Blueprint/docs/11-implementation-plan.md` (M2), `06-scoring-rubric.md`, `07-report-model.md`, `08-run-comparison.md`, `examples/*.json`, `docs/DECISIONS.md` (D10, and D13 added here).

## Global Constraints

- No I/O, no `DateTime.Now`, no randomness in the three components. Output depends only on the inputs.
- Use invariant culture for all formatting. Dates are `dd MMM yyyy`. The score is `0.0` and the percentage is `0`.
- **Rounding:**
  - `qualityScore = Math.Round(Σ(score×weight)/Σweight over scorable, 1, MidpointRounding.AwayFromZero)`, or `null` if nothing is scorable.
  - `weightAssessablePct = Math.Round(Σweight(scorable)/Σweight(all)×100, 0, AwayFromZero)`.
  - Use `decimal` throughout. Check: the sample gives 4.55/0.90 → 5.1 and 90, and the previous sample gives 4.2/0.9 → 4.7.
- **Text templates are exact** (doc 07). These choices aren't in the spec, so record them in D13:
  - Score label:
    - normally `"{score:0.0} / 10 across scored dimensions ({pct:0}% of weight assessable)"`;
    - `"Not scorable"` when the score is null;
    - when `integrationMappedTo != real-seam`, append `" — not comparable to real-seam scores ({mappedTo})"`.
  - Overall bullet: when `unverified/total > 0.25`, append `" (low confidence: many endpoints unverified)"`.
  - "Since last scan" bullet: a null previous or current score prints `N/A`.
- Verdict share = `(covered + 0.5×weak) / (total − unverified)`.
  - Thresholds: ≥0.80 strong, ≥0.60 moderate, ≥0.35 partial, otherwise weak.
  - A zero denominator gives weak.
- Summary counts come from the detail:
  - `falsePositiveCount` = findings of kind `FalsePositive`;
  - `skippedTestCount` = findings of kind `SkippedTest`;
  - `uncoveredRealSeams` = findings of kind `UncoveredSeam` (D13).
- Endpoint identity is `METHOD + " " + route` lower-cased, with every `{name}` → `{}` (doc 08). Lists display the endpoint's own `METHOD route` text: the current run's text for most lists, the previous run's for `removed`.
- List order is deterministic. Use the current report's traversal order (controller order, then endpoint order). `removed` and `findings.fixed`/`risks.dropped` use the previous report's order.
- TDD. Tests are named `Method_Scenario_ExpectedResult`, use Arrange/Act/Assert, and test one behavior each (InlineData/Theory is fine). Fixtures are the linked `examples/*.json`. Mutations use `with` expressions on records, not string edits.
- Serena for code where it works (otherwise say so and use the plain tools). context7 for APIs. One commit per task on `feature/m2-pure-core`. Ask before pushing.

## Review Focus

1. **Division by zero and empty inputs:** no scorable dimension, zero endpoints, or every endpoint unverified. Nothing may throw, and the null/N/A paths must apply. Tested in Task 2.
2. **Route parameter renamed between runs** (`{id}` → `{bookId}`). It's the same endpoint, so it must not show as removed+added. Tested in Task 1.
3. **Unverified transitions** (covered→unverified, unverified→none) go to `confidenceChanged`, never to `regressed` or `newlyCovered`. Tested in Task 1.
4. **A NUL character (`\u0000`) in any report string.** jsonb rejects it at insert, so the validator must flag it before a save is attempted (deferred from M1). Tested in Task 3.
5. **A tampered number that keeps the totals consistent** (for example covered+1 and none−1). Re-derivation must still catch it, so compare each field and don't rely on sums. Tested in Task 3.

### Task 1: RunComparer (doc 08)

**Files:**
- Create: `src/BlindSpotScanner.Application/Reports/RunComparer.cs`, `src/BlindSpotScanner.Application/Reports/EndpointKey.cs`
- Modify: `tests/BlindSpotScanner.Application.Tests/BlindSpotScanner.Application.Tests.csproj` (link `examples/*.json` as `Fixtures/`, as in Domain.Tests)
- Test: `tests/BlindSpotScanner.Application.Tests/Reports/RunComparerTests.cs`, plus `Reports/Fixtures.cs` (a static helper that loads the examples through `ReportJsonSerializer`)

**Interfaces:**
- Produces:
  - `public static class RunComparer { public static RunDelta Compare(IntegrationReport previous, IntegrationReport current); }`
  - `internal static class EndpointKey { public static string Of(EndpointMethod method, string route); }`: lower-cased, with `{…}` → `{}`.
- It reads only `meta`, `inventory`, `endpointCoverage`, `scorecard`, `findings`, `topRisks`, and `summary` counts/score. It never reads `summary.bullets` or `delta`, which keeps it usable by the assembler before the bullets exist.
- **Rules:**
  - `metrics`, exactly these six, in this order:
    - `qualityScore` and `endpoints.covered` (higher is better);
    - `endpoints.weak`, `endpoints.none`, `endpoints.unverified` and `falsePositiveCount` (lower is better).
    - `change = curr − prev`. If either side is null, `change` is null and the direction is `unchanged`.
  - `endpoints`, by endpoint identity:
    - `newlyCovered`: prev ∈ {weak, skipped, none} → covered.
    - `regressed`: covered → weak/none/skipped, or weak → none/skipped.
    - `confidenceChanged`: any transition into or out of `unverified`.
    - `added` and `removed`: present on one side only. `confidenceChanged` is always written (possibly empty).
  - `scorecard`: dimensions (matched by `id`) whose score differs, in id order. Each has `dimension` (the current name), `prev`, `curr`, and `change` (null if either side is null).
  - `findings`: `fixed` = previous stableKeys absent now; `new` = current stableKeys absent before.
  - `risks`: `dropped`/`new` by exact headline.
  - `comparability` reasons, in this order, with the exact strings from doc 08:
    - `endpoint denominator changed: {p} → {c}` (when `endpointsTotal` differs)
    - `integrationMappedTo changed`
    - `profile version changed {p} → {c}`
    - `schema version changed`
    - `model or prompt set changed`
    - `branch differs`
  - `comparable = false` when `integrationMappedTo` differs or `|c−p|/p > 0.20`. A previous total of 0 counts as >20% if the current total is non-zero.
  - `baseRunId`, `baseCommitSha` and `baseGeneratedAt` come from the previous report's meta.
