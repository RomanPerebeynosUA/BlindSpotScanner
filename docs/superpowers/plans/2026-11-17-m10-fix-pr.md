# M10 Fix PR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From a fixable finding, generate an integration test with `prompts/generate-fix.md`, check it with a static guard, show it as an editable diff, and open it as a draft PR through the Git Data API, only on the user's click.

**Architecture:**
- **GitHub writes:** a new write port, `IGitHubPullRequests`, implemented by the existing typed `GitHubClient`, so the scan's read-only `IGitHubClient` is unchanged.
- **Generation and PR:** in Application, `FixContextBuilder` gathers context at the run's SHA, and `FixPullRequests` runs the LLM (the guard acts as its `Validate` callback, so violations trigger a re-ask), builds the draft, checks for staleness and opens the PR.
- **Static guard:** `FixGuard` lives in Infrastructure because it uses Roslyn and `SecretScrubber`.
- **Status refresh:** `RemediationActions` takes over the lazy refresh for both Jira and PR statuses.
- **Web:** a Fix dialog with a client-side line diff, and a "Fix with PR" control hidden in read-only mode.

**Tech Stack:** .NET 10, Roslyn (already referenced by Infrastructure), WireMock.Net, xUnit + FluentAssertions 7; Angular 22 + Material dialog, Vitest, Playwright.

**Spec:**
- `BlindSpotScanner-Blueprint/docs/09-jira-and-pull-requests.md`: "Which items are actionable", "Fix pull request" and "Permissions".
- `docs/04-frontend-angular.md`: "Fix-with-PR dialog".
- `prompts/generate-fix.md` v1.0.0.
- `docs/10-security-config-ops.md`: `Features:PullRequests`.
- `docs/11-implementation-plan.md`: M10.
- The user's M10 answers, recorded as D25 in Task 1.

## Global Constraints

- **M10 AC:**
  - WireMock GitHub asserts the sequence branch → blobs → tree → commit → ref → PR (draft);
  - the guard rejects a production-code edit;
  - read-only mode hides the button.
- **Fixable kinds (D25):** `UncoveredEndpoint` creates a new test; `WeakTest` and `FalsePositive` modify the existing test; `SkippedTest` removes the skip, or the LLM declines with `files: []`. `UncoveredSeam` and `Risk` get no PR.
- **Stale files (D25):** if a target file differs between the run SHA and the current default-branch HEAD, create returns 409 with the changed paths. The dialog offers "Regenerate"; there is never an automatic billed call.
- **Tests:** WireMock only, no live test (D25).
- **Branch:** `coverage/fix-<stableKey-slug>-<shortsha>`. The slug is lowercase, every run of non-`[a-z0-9]` characters becomes one `-`, it is trimmed of `-` and cut to 40 characters; `shortsha` is the run's first 7 SHA characters.
- **PR:** a **draft** against the default branch, labelled `integration-coverage`. The body includes the rationale, assumptions, a report link, the finding and the Jira key if one exists, and ends with the line `Generated by BlindSpotScanner — review before merging; CI must pass.` (D5 renamed the app).
- **Guard:**
  - every path is inside the test project folder (the folder of the nearest `.csproj` above the sibling tests);
  - only `.cs` files, which also means no project edits and so no new packages;
  - no `..`, no leading `/`;
  - `create` only for a path that doesn't exist at the SHA, `modify` only for one that does;
  - at most 5 files and 100 000 characters per file;
  - `SecretScrubber.Scrub(content) == content`;
  - no Roslyn syntax errors.
- **Read-only:** `Features:PullRequests` (default `true`) **and** a configured `GitHub:Token`. Otherwise the fix endpoints return 403 and the UI hides "Fix with PR".
- **Principles:** principle 8 (a human click after a preview; the server re-runs the guard on whatever the client sends) and principle 9 (no token in errors; content is scrubbed before the LLM, which `ILlmClient` already does).
- The app never runs the generated test; CI on the PR is the verification.

## Review Focus

1. **The client posts files the guard never saw** (edited content, or a crafted request). Create re-runs the guard on the submitted files and returns 422 with the violations. Test: `CreateAsync_EditedFileOutsideTestProject_Returns422WithoutCallingGitHub` (Task 5).
2. **The branch already exists** (a second PR attempt for the same finding and SHA). GitHub answers 422 on the ref creation. The user gets a 409 "Branch … already exists; rename it" and no orphan PR. Test: `CreatePullRequestAsync_RefExists_ThrowsBranchExists` (Task 1).
3. **The LLM keeps breaking the guard.** After 2 re-asks the preview fails with the guard's messages (422), and nothing is shown as committable. Test: `PreviewAsync_GuardFailsEveryAttempt_ReturnsRejectedWithReasons` (Task 4).
4. **A path traversal or a case trick** (`tests/Bookstore.IntegrationTests/../../src/Api/X.cs`, or a backslash path). The guard normalises first, so these are rejected. Test: `Check_DotDotEscape_Rejected` and `Check_Backslashes_Rejected` (Task 3).
5. **GitHub fails halfway** (blob and tree created, PR call 500s). No action is stored, and the error is a 502 that names the step. The created branch is left as it is, and the message says so. Test: `CreateAsync_PullCallFails_StoresNothing` (Task 5).
