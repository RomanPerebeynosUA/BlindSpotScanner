# M11 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close v1 with sign-in and roles, real `CreatedBy`, the per-repository "LLM data sharing" acknowledgement, structured logs with redaction, OpenTelemetry, report export (JSON and printable HTML), a read-only settings status page, and a security checklist whose items are proven by tests.

**Architecture:**
- **Sign-in:** the API owns it, with server-side OIDC and a cookie session (the BFF pattern), so the browser never handles tokens.
  - `Auth:Mode` = `Local` gives every request a local admin; this is the default for development and compose.
  - `Auth:Mode` = `Oidc` uses OpenID Connect against any provider.
  - Three policies (Viewer, Member, Admin) guard the controllers and the hub.
  - An `ICurrentUser` port feeds `CreatedBy`.
- **Logs:** Serilog writes JSON, with a destructuring policy and a message scrubber that redact secrets.
- **Telemetry:** OpenTelemetry carries an `ActivitySource` and a `Meter` named `BlindSpotScanner`, exported over OTLP only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set.
- **Export:** an endpoint renders escaped, self-contained HTML.
- **Web:** a `/api/me`-driven user bar, controls gated by role, a settings page, export links and the acknowledgement dialog.

**Tech Stack:**
- .NET 10 / ASP.NET Core authentication: Cookies, `Microsoft.AspNetCore.Authentication.OpenIdConnect`;
- `Serilog.AspNetCore` and `Serilog.Formatting.Compact`;
- the OpenTelemetry .NET packages: `OpenTelemetry.Extensions.Hosting`, `OpenTelemetry.Instrumentation.AspNetCore`, `OpenTelemetry.Instrumentation.Http`, `OpenTelemetry.Exporter.OpenTelemetryProtocol`;
- EF Core 10 and WireMock.Net;
- Angular 22, Vitest and Playwright.

## Global Constraints

- **Answers (D26):**
  - server-side OIDC with a cookie, plus a built-in local admin;
  - the settings page is read-only status with masked values and Test buttons; values stay in env vars, and nothing is stored in the DB;
  - the GitHub PAT stays, and a GitHub App is out of v1.
- **Roles (doc 10):**
  - `Viewer` reads;
  - `Member` also adds repositories, edits profiles, acknowledges LLM sharing, scans, cancels, and creates Jira tickets and PRs;
  - `Admin` also gets `/api/settings/*`.
  - Admin includes Member, and Member includes Viewer.
  - With no auth, requests get 401; with the wrong role, 403. `/health` and `/api/auth/*` stay anonymous.
- **OIDC config:**
  - `Auth:Authority`, `Auth:ClientId`, `Auth:ClientSecret` (an env var, never appsettings), `Auth:RoleClaim` (default `roles`) and `Auth:DefaultRole` (default `Viewer`);
  - `CallbackPath` = `/api/auth/callback`, so the existing nginx `/api/` proxy covers it;
  - the cookie is HttpOnly, Secure (SameAsRequest in development), and SameSite=Lax;
  - an API request without a session gets 401, never a redirect.
- **`CreatedBy`:** the signed-in user's name or email claim, falling back to `sub`; the local admin is `local-admin`.
- **LLM sharing (doc 10):** a repository needs `LlmSharingAcknowledgedAt` set before its first scan. Until then `POST …/scans` returns 409 with the title `LLM data sharing not acknowledged`.
- **Secrets:**
  - never returned by the API (masked as `••••` plus the last 4 characters; 4 characters or fewer show only `••••`);
  - never logged: the destructuring policy redacts the properties `Token`, `ApiKey`, `ApiToken`, `ClientSecret`, `Password`, `Secret` and `Authorization` (case-insensitive), and `SecretScrubber` runs on rendered messages;
  - an `appsettings.Example.json` is shipped, and committed `appsettings*.json` files hold no secret values.
- **Logs:** Serilog compact JSON to the console, with `runId` and `phase` as scope properties during scans.
- **Telemetry (doc 10):**
  - one span per phase (`scan.phase` with the tag `phase`), as a child of a `scan.run` span;
  - HttpClient spans are children automatically;
  - metrics:
    - `bss.scan.duration` (histogram, seconds);
    - `bss.scan.tokens` (counter, tag `direction` = input|output);
    - `bss.scan.cost` (counter, USD);
    - `bss.scan.failures` (counter, tag `reason`, the first failure reason's first 60 characters);
    - `bss.github.ratelimit.remaining` (observable gauge from the last response header).
- **Export:** `GET /api/runs/{runId}/export?format=json|html` (default `json`).
  - JSON is the stored report served as-is, with `Content-Disposition: attachment; filename="report-<owner>-<name>-<shortsha>.json"`.
  - HTML is a self-contained page with inline CSS and no scripts, and every report string is HTML-encoded. It has `@media print` styles and the same filename pattern with `.html`.
  - A run without a report returns 409.

## Review Focus

1. **A crafted report string with `<script>` or `"><img onerror=…>` in finding text** (LLM-authored). The HTML export encodes it, and the page has no inline script. Test: `Export_Html_EncodesFindingText` (Task 6).
2. **An OIDC user without a role claim, or with an unknown role value.** They get `Auth:DefaultRole`, Viewer by default; unknown values are ignored, never elevated. Test: `Roles_UnknownClaimValue_FallsBackToDefault` (Task 1).
3. **The SignalR hub without a session.** Negotiate and connect are refused with 401, so progress events don't leak. Test: `Hub_Anonymous_Returns401` (Task 1).
4. **A secret inside a log message**, not only in a property: for example an exception message carrying a connection string. The scrubber redacts the rendered message. Test: `Log_ExceptionMessageWithConnectionString_IsRedacted` (Task 4).
5. **A secret of 4 characters or fewer, or an empty one.** The mask never reveals it. An empty value reads as "not configured", and a 3-character value shows `••••`. Test: `Mask_ShortSecret_RevealsNothing` (Task 7).

**Interfaces:**
- Produces:
  - `public static class Roles { public const string Viewer = "Viewer", Member = "Member", Admin = "Admin"; }`, with policy names equal to the role names.
  - `RoleClaims.Effective(IEnumerable<string> claimed, string defaultRole) : string` returns the highest known role claimed, or `defaultRole`.
  - `GET /api/me` returns `{ name, roles: string[] }` (200, or 401 without a session).
  - `GET /api/auth/login?returnUrl=/…` challenges OIDC. Only a local `returnUrl` (starting with `/`, not `//`) is accepted; anything else becomes `/`.
  - `POST /api/auth/logout` signs out of the cookie and OIDC.
  - In Local mode, login redirects straight to `returnUrl`.

**Policy map:**

| Policy | Endpoints |
|---|---|
| Viewer | every GET; `/hubs/scans` |
| Member | `POST /api/repositories`; `PUT …/profile` and `POST …/profile/draft`; `POST …/scans`; `POST runs/{id}/cancel`; `POST …/llm-sharing` (Task 3); every Jira and fix POST |
| Admin | `/api/settings/*` |
