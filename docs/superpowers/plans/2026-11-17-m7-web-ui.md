# M7 Angular UI: Repositories, Live Scan, Report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user can add a GitHub repository (which gets a default profile), edit or AI-draft its
profile, start a scan, watch it live, and read the report with status filters, search and
drill-down. Playwright tests against an API mocked from `examples/` prove the whole journey.

**Architecture:** Backend: the repository and profile endpoints deferred from M6 (D21).
Application gets `RepositoryService`, `ProfileService` and `ProfileDrafter` behind the ports
`IRepositoryStore` and `IProfileStore` (EF implementations), plus thin `RepositoriesController` and
`ProfilesController`. Frontend: the blank `src/web` scaffold becomes an Angular Material app with
a nav-rail shell, hand-written typed API services, a ProblemDetails→snackbar interceptor, a
SignalR `ScanProgressService` and lazy routes for five pages. Compare, the run picker, delta chips
and the sparkline are M8; Jira/PR buttons and the actions log are M9/M10; settings is M9.

**Tech Stack:** .NET 10, ASP.NET Core controllers, EF Core 10 + Npgsql, xUnit + FluentAssertions,
Testcontainers, WireMock.Net · Angular 22 (standalone, signals, `inject()`), Angular Material + CDK,
`@microsoft/signalr`, `marked` (Markdown preview), Vitest via `ng test`, `@playwright/test`.

**Spec:** `BlindSpotScanner-Blueprint/docs/04-frontend-angular.md` (routes, report layout, state),
`ui-prototype/index.html` (visual target: tokens, layout, chips, KPI tiles, stepper, tables),
`contracts/openapi.yaml` (repository/profile/scan/run paths, `RepositorySummary`, hub messages),
`contracts/integration-report.schema.json` + `examples/` (report shape and fixtures),
`prompts/draft-profile.md` + `profiles/_template.md` (AI draft), `docs/03-backend-dotnet.md`
(API surface), `docs/11-implementation-plan.md` (M7 AC), `docs/DECISIONS.md` (D17, D18, D20, D21).

## Global Constraints

- AC (doc 11): Playwright tests using the API mocked from examples cover add repo → scan → live
  progress → report with filters and drill-down.
- User's choices (this plan, recorded as D22 in Task 1): adding a repo saves profile v1 from
  template defaults, and the profile page also offers "Auto-draft with AI"; the profile editor
  edits the typed D18 columns and the Markdown; no settings page until M9; hand-written API
  services instead of openapi-generator.
- Principle 8: the AI draft is only a preview; nothing is saved until the user clicks Save (PUT).
- Principle 9: denied paths (`LlmContentPolicy`) are never sent to the draft prompt; the LLM goes
  through `ILlmClient` (scrubbed, schema-validated, max 2 re-asks).
- Principle 1 in the UI: status is always icon + text (`✅ Covered`, `⚠️ Weak`, `⏭️ Skipped`,
  `❌ None`, `❔ Unverified`); a null score shows `N/A`, never `0`.
- New endpoints return errors as ProblemDetails (`AddProblemDetails()`); the web interceptor shows
  `detail ?? title` in a snackbar and rethrows.
- Hub: `/hubs/scans`, client calls `Subscribe(runId)`; server sends `ScanProgress(runId, phase, pct,
  message)` and `ScanCompleted(runId, status)`. Phases: `P1 P2 P3 P4 P4b P5 P6 P7`
  (`ScanPhases.All`). Events are best effort, so the live page also polls `GET /api/runs/{id}` (D21).
- Visual: the prototype's CSS tokens (`--bg … --unk-bg`, fonts IBM Plex Sans/Mono + Space Grotesk),
  light/dark via `prefers-color-scheme` and `data-theme` on `<html>`, rail collapses at ≤800px,
  no horizontal page scroll at 360px.
- Frontend rules: one component per folder (`name.ts/.html/.scss/.spec.ts`, D7), signals for local
  state, HTTP only in services, strict TS, no `any` without a comment. Look up Angular Material,
  SignalR and Playwright APIs with context7 before using them.
- Backend tests `Method_Scenario_ExpectedResult`, AAA comments, one behavior, no branching.

## Review Focus

1. **The same repository added twice** (two clicks, or URLs that differ by case, `.git` or
   `/tree/x`): one repository row; the second add returns 409 with the existing id (Task 1
   `AddAsync_SameRepositoryDifferentUrlForm_ReturnsAlreadyRegistered`, Task 2 `TryAddAsync_DuplicateName_ReturnsFalse`).
2. **Two people save the profile from the same version**: the second save gets 409 and overwrites
   nothing (Task 3 `SaveAsync_StaleBaseVersion_ReturnsConflict`).
3. **The hub drops or `ScanCompleted` is lost**: the live page still reaches the report through the
   poll (Task 10 `completion_seenOnlyByPoll_navigatesToReport`).
4. **An unscorable or empty report** (null score, every endpoint unverified, no findings, a filter
   that hides everything): `N/A`, "No endpoints with this status", "None." and no crash (Task 11
   `scoreTile_nullScore_showsNA`, `coverage_filterHidesAll_showsEmptyRow`).
5. **A phone at 360px**: the report and repositories pages have no horizontal page scroll (Task 12
   `report_at360px_hasNoHorizontalScroll`).
